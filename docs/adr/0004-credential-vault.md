# 0004：系统密钥保险库与可选记住登录

日期：2026-10-26。状态：实现完成；真实安全密钥后端与跨重启恢复待验证。

## 背景

网易云与酷狗目前使用临时会话，关闭应用后需要重新扫码。产品需要在不把 Cookie/Token 写入明文文件、页面存储或日志的前提下，提供可选的记住登录；同时必须在系统密钥服务不可用或锁定时退回临时会话，而不能伪造成功。

Electron `safeStorage` 在 Linux 的后端取决于桌面密钥服务。`basic_text` 只是可逆编码，不能当作保护；同步旧接口也不适合作为唯一安全判断。凭据还必须与平台、客户端渠道和账号对应，恢复时重新验证身份。

## 决定

- 在主进程实现 `CredentialVault`，用 Electron `safeStorage` 异步接口加密平台凭据 bundle。
- Linux 只接受 libsecret/KWallet 后端；`basic_text`、未知或不可用后端一律拒绝持久化，登录保持临时会话。
- 凭据文件放在 `userData/credentials.json`，目录 0700、文件 0600，使用同目录临时文件加重命名；外层只保存版本、记住开关、平台键、密文和更新时间。
- 用户显式勾选“记住登录”后才保存；关闭或清除保存删除全部，退出某一个平台删除该平台保存项。
- 登录成功后后台导出白名单凭据给主进程；启动恢复时后台重新调用账号接口验证，不凭“可解密”进入 connected。失效会话删除保存项，网络失败保留密文并显示失败。
- 解密失败进入 locked 状态，不覆盖原文件；用户可清除后重新登录。密钥轮换提示暂不自动重新加密。

## 备选与影响

直接在 renderer 或数据库保存明文 Cookie/Token 被拒绝；在 Provider 进程内自行写文件也会扩大凭据暴露面。完整系统 Keychain 库或自定义密码派生方案需要额外依赖、解锁流程和跨平台审计，暂不引入。

safeStorage 的异步后端在 Linux 仍可能回退到弱后端，因此必须用 `getSelectedStorageBackend` 做显式判断。开发机当前只有 `basic_text`，真实密钥服务、锁定和重启恢复无法在本机完成；这属于验证限制，不是功能已通过。Windows/macOS 后端也需后续验证。
