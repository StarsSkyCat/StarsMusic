# 0003：酷狗 App 扫码临时会话与渠道隔离

日期：2026-10-26。状态：已采纳实现方向；匿名与合成验证通过，真实账号闭环待用户验证。

## 背景

酷狗提供网页登录与 App 扫码两条候选路径，两者的 Cookie/Token 渠道和可用接口不同。项目要求临时会话、不落盘凭据、不向页面暴露通用请求接口，并需要读取私人歌单和解析播放资源。首个渠道应能用较小攻击面完成登录、歌单与播放验证，同时保留另一渠道的独立验证空间。

## 决定

首版只实现标准版酷狗 App 扫码（`kugou-app`），不实现官方网页登录窗口。登录前先注册临时设备取得 `dfid`，再获取二维码 key，由用户在官方 App 内确认；状态 4 返回的 `userid`/`token` 必须再经账号接口验证后才进入 connected。

固定 KuGouMusicApi 1.6.2 的协议基线，以 Node crypto/fetch 实现白名单端点，不加载完整 SDK。平台请求、设备标识、Token、二维码 key 和签名媒体地址只存在于酷狗专用 utilityProcess；页面只收公开 DTO、二维码和已登记曲目 ID。歌单与播放参数使用页面不可见的后台映射，媒体经按平台隔离的 loopback 网关交给 mpv。

网页 Cookie 与 App Token 不互相导入，不共享会话、设备标识或缓存。网页登录保留为后续独立验证项，未验证前不把网页渠道写成可用。

## 备选与影响

官方网页登录窗口可复用用户熟悉的网页授权，但需要额外验证隔离 session、Cookie 提取范围、退出清理以及网页凭据能否调用 App 接口；若只拿到身份而拿不到播放凭据，会增加一个不完整状态。App 扫码少一层网页会话，但 Token 与设备绑定，需要正确注册 `dfid`，并可能在云歌单或取链时遇到风控和 Token 作用域限制。

App 扫码的代价是首版不能覆盖网页渠道，且当前没有 Token 自动刷新；登录保存最初由 [ADR 0004](0004-credential-vault.md) 补充，随后按 [ADR 0005](0005-local-key-sqlite.md) 改为本地随机密钥与 SQLite，真实账号跨重启仍待验收。协议依赖社区维护的固定基线，上游变更需要重新验证；SSA 安全验证只提示用户处理，不尝试绕过。真实账号与不同曲目权限矩阵尚未验证，不能从匿名端点或合成响应推断接入完成。
