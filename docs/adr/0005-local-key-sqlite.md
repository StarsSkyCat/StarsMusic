# 0005：本地随机密钥与 SQLite 登录保存

日期：2026-10-26。状态：已实现；取代 [ADR 0004](0004-credential-vault.md)。真实账号重启恢复与发行包尚待验收。

## 背景

用户明确希望使用 SQLite 保存扫码登录后的凭据，避免目标桌面缺少 GNOME Keyring/KWallet 导致无法记住登录。SQLite 提供持久存储，本身不解决密钥保管；需要明确便利性与本地隔离的取舍。

## 决定

凭据以随机 32 字节本地密钥、AES-256-GCM 和每次独立 nonce 加密后存入版本化 SQLite。密钥与数据库分文件，Linux 目录 0700、文件 0600；只在用户启用记住后保存，UI 明确提示同获数据库与密钥即可解密。新保存不依赖系统密钥服务，不提供明文回退或固定密钥。

使用 Node/Electron 内置 node:sqlite，在独立 Node worker 中执行全部同步 SQL；主进程异步协调，renderer 无 SQL、密文或密钥接口。保留双平台渠道隔离、账号重新验证和迟到操作撤销。损坏/未来版本不自动覆盖，明确清除才重建；旧系统密钥文件可解密时才事务导入并删除原文件。

## 备选与影响

保留系统密钥方案会继续受目标桌面服务影响；要求每次输入主密码会增加用户操作；明文 SQLite 或内置固定密码不能满足当前不静默明文保存的规则。选择本地随机密钥使记住登录可独立工作，但不保护同用户恶意程序或整个数据目录泄漏，不能等同系统密钥库。

没有新增 npm/native SQLite 绑定，不需要安装数据库服务；仍需验证实际发行运行时和文件系统。SQLite 此时只保存凭据，不代表音乐库、缓存或队列恢复已实现。

## 验证

真实 SQLite/AES 合成回归、禁用系统密码库下的 Electron 记住设置重启、PipeWire 桌面与退出通过；真实平台扫码后的跨重启验收、安装包和 Windows/macOS 待验证。结果见 [SQLite 记录](../validation/2026-10-26-sqlite-credentials.md)，范围与用户流程见 [凭据说明](../credentials.md)。
