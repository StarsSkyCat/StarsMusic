# P0 本地音频闭环验证

## 基本信息

- 日期、执行者：2026-10-26，Codex 本地开发会话。
- 目标：P0 第三步，本地文件播放、私有 IPC、定位、快速切歌与退出清理。
- 结果：通过本次 Linux 本地播放范围；安装包、完整格式矩阵和在线资源未执行。
- 工作区：前两步提交 e953566 之上的第三步改动，本步骤验证后单独提交。
- 系统：Arch Linux rolling、x86_64，当前图形会话 Wayland，Electron 45.0.0。
- Node.js 24.22.1、pnpm 10.34.9；mpv 0.41.0（系统包 1:0.41.0-6），FFmpeg 运行时 n9.0.2。
- 资源：测试时现场生成的静音 PCM WAV，包含中文/空格文件名；无真实平台、账号、凭据或第三方音频资产。

## 操作与实际结果

1. typecheck：主进程、preload、Vue、契约、后台播放器及测试源码通过。
2. test：16 项单元测试通过，包括播放命令参数、数值、队列索引和快照路径过滤。
3. test:playback：3 项真实 mpv 场景通过，使用 null 音频输出，未跳过缺依赖检查。
4. test:e2e：构建后运行实际 Electron，保留 Chromium 沙箱；替换原生文件选择器返回合成 WAV，实际 mpv 选择系统 PipeWire（current-ao=pipewire），执行播放、暂停、5 秒定位和恢复，关闭窗口后确认 mpv PID 不存在。
5. 实际截图已查看，覆盖 1280×800 与 960×640 视口，本地队列和播放控件可访问；截图在 Git 忽略的 artifacts/。
6. check 与 git diff --check：文档、本地链接、配置及差异格式通过。

## 负向、竞态与清理

- IPC 拒绝未知命令、任意路径参数、额外参数、NaN/Infinity、负定位和超过 100 的音量；快照不包含真实文件路径。
- 私有继承 FD 实际握手、并行请求关联、无效命令失败、后续命令继续可用、头清空通过；命令行不含测试头或监听 socket。
- 重复 start 被拒绝，快速多次切歌只启动最终有效项目；新实例播放前旧 PID 已退出，当前只有一个 mpv 子进程。
- 切歌保留用户音量，修复并回归了新实例默认音量覆盖用户音量的问题。
- mpv 被 SIGKILL 后状态为错误；用户显式重播可恢复，不进行无限重启。
- EOF、损坏文件、缺失文件、伪装成 WAV 的 M3U 引用、缺失 mpv 均未冒充成功；快速开始后立即停止不残留进程。
- stop、dispose 和应用关闭均确认无遗留 mpv；临时音频与配置目录被清理。

## 限制与后续

PipeWire 输出驱动确实打开，但使用静音测试音频，没有人工听音检查；不代表扬声器、蓝牙切换、休眠恢复或音质已验证。受限环境仍可能出现 DRM/GPU/NSS/D-Bus 警告，未据此关闭沙箱或宣称硬件加速兼容。

原生文件选择器的真实人工操作、其他音频格式、X11 独立桌面、其他发行版、安装包和 Windows/macOS 未验收。CI 已配置系统 mpv 与 null 输出测试，尚未观察远端运行结果。

在线资源、凭据头/重定向隔离、自动续播/循环/随机、持久本地音乐库、歌词和 MPRIS 均未实现。下一步按路线图验证网易云平台接入，真实账号授权由用户在官方流程中完成。
