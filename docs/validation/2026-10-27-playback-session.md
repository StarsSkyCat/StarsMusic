# 播放会话保存与音量交互

日期：2026-10-27。按用户要求保存队列、音量和进度，改善音量滑条。

## 第一步：音量

音量滑条由 change 改为 input 即时本地反馈，35 毫秒合并、单路串行发送最新值，拖动不受旧状态抢占。后台同步投影用户目标，合并 mpv 音量命令，忽略旧音量回报。滑条操作区增至 44px、滑块增大，保留原生方向键/Home/End，增加滚轮和数值显示。独立静音保留音量，零音量取消静音可恢复上次非零值。

验证：`pnpm typecheck`、`pnpm test`（101 项）、`pnpm test:playback`（5 项真实 mpv）、`pnpm test:e2e`（8 项）及 `pnpm check` 通过。桌面测试验证连续拖动、旧响应不抢占、请求合并、键盘和静音；真实音频输出为 PipeWire。首次桌面检查发现全局 range 样式压缩操作区，已修正选择器并重新通过全套桌面测试。

## 第二步：播放记录

- 单独的 `playback.sqlite` 由 Node worker 保存，严格字段白名单，只记录队列元数据、路径、原账号、顺序、当前 ID、位置/时长、音量/静音和上次非零音量。账号凭据仍走独立加密存储，签名流地址与旧权限不落盘。
- 队列和设置更新合并 200ms、进度每 3 秒保存；正常退出先冲刷记录，再停止播放器和平台后台。强制终止/断电可能丢失尚未提交的数秒进度。SQLite 事务失败保留上次记录，损坏/未知版本保留原库并显示独立保存错误。
- 启动恢复为暂停且不创建 mpv；用户点击继续才根据书签使用 `--start` 解码。可以在恢复暂停时调整进度。文件丢失和取链失败保留恢复书签供重试。
- 在线队列按平台/原账号绑定。未登录不清空停放队列，点击播放提示连接原账号；连接另一账号清除该平台原账号曲目，显式退出清除该平台并保存删除。恢复曲目重新登记并走现有权限/身份校验；本次只能试听时不沿用旧整曲位置越界播放。
- 桌面重启测试覆盖三次启动、重排、当前项、进度、音量、静音、移除后的保存、暂停启动无 mpv、点击后真实 PipeWire 输出。另一个测试只用合成在线记录启动实际后台，验证匿名状态保留队列、未登录恢复失败保留书签、显式平台退出及再次重启后的删除结果；没有模拟真实账号验证成功。
- 音量压力测试揭示拖动请求尚未完成时静音可能被迟到响应覆盖；现已把静音排在未完成的音量提交之后，并验证通过。

实际检查：`pnpm typecheck`、`pnpm test`（109 项）、`pnpm test:playback`（7 项真实 mpv）、`pnpm test:e2e`（10 项，包含构建）及 `pnpm check`。真实 mpv 测试覆盖恢复前无音频进程、书签解码和旧完整书签受本次试听长度约束。暂停后的实际位置受音频缓冲影响，恢复检查比较保存时实际位置，不把 seek 目标冒充实际 mpv 进度。
