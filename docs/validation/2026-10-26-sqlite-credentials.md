# SQLite 登录保存验证

日期：2026-10-26。Linux x86_64、Node.js 24.22.1、Electron 45；实际音频为系统 mpv / PipeWire。按用户要求取消新登录保存对系统密钥服务的依赖，使用本地随机密钥与 SQLite。

## 实现

- 凭据先用 AES-256-GCM 加密，SQLite 只接收密文；数据库与随机 32 字节密钥分文件存放，Linux 权限为目录 0700、文件 0600。每次加密有新的随机 nonce 与认证标签。
- 内置 node:sqlite 随运行时提供；所有同步 SQL 在专用 Node worker 中执行。没有新增 npm 包或系统服务，preload 方法不变，没有数据库/密钥/任意 SQL 的公开 IPC。
- 数据库版本、原子事务与回滚、旧加密 JSON 转换、密钥丢失/损坏保护、显式清除重建已接通；保留既有账号重新验证及撤销竞态保护。
- UI 明确说明本地保护边界：同时取得数据库与密钥文件即可解密；未把该方案描述成系统密钥库隔离。

## 执行结果

- `pnpm check`：文档、相对链接和配置检查。
- `pnpm typecheck`：严格 Node/Vue 类型检查。
- `pnpm test`：68 项通过。凭据新增真实 SQLite/AES 测试：双平台保存与关闭后跨实例恢复、明文合成凭据不出现在数据库、权限、随机 nonce、密钥缺失不覆盖、错误密钥/篡改拒绝、未来版本与损坏库保留、事务失败不丢旧记录、旧文件可解密才导入且事务提交后删除。
- `pnpm test:e2e`（含构建）：2 项通过。主桌面使用实际 mpv/PipeWire，保存开关在 `--password-store=basic` 下仍可用；第二项实际关闭 Electron 后重启，确认已启用设置保留，再清除。只使用临时独立 profile，不注入账号、不调用真实登录；应用与 SQLite 线程正常退出。
- `pnpm test:playback`：5 项实际 mpv 集成回归。

自动化凭据全部为明确标识的合成数据，临时数据库/密钥在测试后删除；不读取真实用户凭据，不提交数据库、密钥、二维码、歌单截图或平台响应原文。

## 限制

实际 Electron 重启测试验证的是 SQLite 后台与记住设置；双平台凭据加密恢复以真实 SQLite/AES 的跨实例测试及 Provider 合成恢复测试覆盖，**不是用户真实登录闭环**。用户仍需在官方扫码后关闭/重启，确认平台账号重新验证成功。过期 Token 需要重登；服务端撤销不能由本地存储解决。

旧系统密钥不可用时保留旧文件并允许重新扫码保存到新库，不伪造迁移成功。安装包、断电/文件系统故障、Windows/macOS 权限和运行时兼容尚未验证；SQLite 音乐库、播放队列恢复与本地音乐索引不在本轮范围。

使用方式与保护边界见 [凭据说明](../credentials.md)，旧方案记录见 [历史验证](2026-10-26-credentials.md)。
