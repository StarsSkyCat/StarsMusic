# P0 网易云验证

## 基本信息

- 日期、执行者：2026-10-26，Codex 开发检查与用户本机官方 App 手动授权。
- 目标：固定协议基线，扫码 → 账号 → 私人歌单 → 流解析 → 实际播放。
- 结果：本次账号闭环通过；权限、音质和分发矩阵仍受限。
- 基于 da9902b 的第四步实现；验证后单独提交。
- 环境：Linux x86_64，开发基线 Arch rolling、Node 24.22.1、pnpm 10.34.9、Electron 45.0.0、mpv 0.41.0；此前本机默认音频为 PipeWire，不外推用户所有设备和桌面。
- 网易云渠道：netease-app 扫码；协议基线 api-enhanced 4.41.1 / 2db6684453297ee86dec0492842f2320b08182d9。

## 操作与实际结果

1. 审查候选 SDK 默认入口、传输、二维码和流接口源码及许可；选取固定协议格式实现所需白名单请求，不加载 SDK 共享文件/日志/解锁模块。
2. probe:netease 实际匿名调用二维码 key 接口成功；仅打印通过状态，不输出 key 或二维码，也不登录账号。
3. 用户在应用里用官方 App 授权，反馈扫码、昵称和歌单读取/打开正常；没有接收或保存其凭据。
4. 用户首次反馈只有播放失败。应用已解析出实际资源与音质，但网关返回失败。
5. 用上游公开示例的匿名资源复现：普通 HTTPS Range 返回 206、audio/mpeg；网关原先把 DNS 代理的 Fake-IP 池误判为不可连接地址，返回 502。修复为兼容 198.18.0.0/15 映射，保留 CDN 主机与 TLS 身份限制。
6. 修复后同一匿名诊断路径的网关返回 206、audio/mpeg，实际 mpv 通过 null 输出完成真实资源解码，状态 playing；签名地址全程不展示、不落盘。
7. 用户按重启后复测路径反馈“已正常出声”。该项是用户人工听音证据，不是从 HTTP 状态或昵称推断播放成功。

## 安全与隐私

真实账号名、账号 ID、个人歌单内容、用户截图、二维码、Cookie、Token 和签名媒体 URL 均未写入仓库、日志或测试快照。自动化使用明确标识的合成输入；用户反馈只记录阶段结果。临时凭据仅在后台进程内存，退出/重启需要重新扫码。
