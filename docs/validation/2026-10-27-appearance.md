# 双主题与外观偏好

日期：2026-10-27。针对用户提出的全程序配色要求，实现浅色、暗色和跟随系统。播放页高度布局另一步处理，本记录只描述外观。

## 当前能力

- 账号与设置最上方新增「外观与配色」，采用原生单选框，支持键盘焦点及方向键。默认跟随系统，运行时桌面颜色方案变化即切换；显式浅色/暗色不受系统变化影响。
- 云瓷白使用透白玻璃、细灰边缘、柔和阴影与深绿主操作；曜石黑使用中性炭黑、冷银高光和少量薄荷强调色。文字、按钮、来源卡、歌单、列表、账号、歌词、队列和错误状态共用语义颜色，扫码图像保留白底。
- renderer 挂载前读取已保存选择，主窗口底色同时按偏好/系统初始化；不会为了主题改用持久浏览器 session。外观文件不含账号、队列、凭据或媒体地址。
- 设置即时预览，保存失败回退到原主题和原单选状态并显示错误，可修复后重试。

## 边界

新增 appearance.getPreference / setPreference 具体接口，输入只能是 system / light / dark；preload 校验输入与响应，主进程验证可信窗口、主帧、主文档以及精确参数数量。不提供任意配置或路径读写能力。

主进程通过异步文件操作将 `{ version: 1, theme }` 保存到 userData/appearance.json，写入串行排队并以临时文件原子替换。读取缺失、损坏或未知版本时使用系统模式；原文件保留，只有用户重新选外观才写入。保存失败保留内存旧偏好。没有新增依赖或更改凭据存储。

## 验证

- `pnpm typecheck`：主进程、preload、Vue 与测试类型检查。
- `pnpm test`：75 项，新增外观参数拒绝、实际文件持久化/并发顺序、损坏回退和写入失败恢复。
- `pnpm test:e2e`（含构建）：4 项，新增浅色/暗色切换、模拟系统颜色方案变化、显式主题优先、实际 Electron 重启恢复，以及保存失败 UI 回退/重试。既有 mpv / PipeWire 播放和安全边界回归保留。
- `pnpm check`：文档与相对链接检查。
- 检查 artifacts/theme-light-settings.png、theme-dark-settings.png；隔离配置，不获取真实平台二维码或私人账号截图。

当前验证限本机 Linux 开发环境。系统跟随测试使用浏览器颜色方案模拟，不代表所有 Linux 桌面配置/portal 或 Windows/macOS 已验收；没有完成完整 WCAG 或跨 GPU 性能审计。
