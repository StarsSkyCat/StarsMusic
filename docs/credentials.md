# 凭据持久化

已实现基于 Electron `safeStorage` 的临时凭据保险库：登录成功后，主进程把对应平台的凭据加密保存到应用用户数据目录；下次启动时只在系统密钥后端可用且用户启用“记住登录”时尝试恢复。默认仍是临时会话，不保存凭据。

## 后端与边界

- 使用 `safeStorage` 异步接口，不使用同步旧接口。
- Linux 只接受 `gnome_libsecret`、`kwallet`、`kwallet5`、`kwallet6` 后端；`basic_text` 只是可逆编码，不是系统密钥保护，直接视为不可用。其他平台使用系统提供的 safeStorage 后端。
- 系统密钥服务不可用时，界面显示原因，登录保持内存临时会话；不写明文、不伪造“已保存”。
- 凭据文件位于 Electron `userData` 目录下的 `credentials.json`；目录权限尝试设为 0700，文件写入后设为 0600，并通过同目录临时文件加重命名尽量保持原子性。
- 文件外层只包含版本、是否记住、平台键、密文和更新时间；Cookie、Token、设备标识、账号 ID 和昵称都在密文内。

## 用户流程

1. 在“登录保存”面板勾选“记住登录”。如果系统密钥服务不可用，勾选不会生效，并显示固定错误文案。
2. 正常完成网易云或酷狗 App 扫码。后台在账号验证完成后把凭据交给主进程；只有已启用记住且后端可用时才加密写入。
3. 退出应用时保留密文，不保留渲染进程或后台进程中的明文。
4. 下次启动时，如果记住仍启用且密钥后端可用，主进程解密并向对应后台进程发送恢复请求；后台重新调用账号接口验证身份，成功后进入 connected，失败则清理内存状态并显示错误。
5. 退出某个平台会删除该平台的保存项；关闭“记住登录”或点击“清除已保存登录”会删除所有保存项。删除不会撤销平台侧会话。

## 平台凭据内容

- 网易云：`netease-app` 渠道的 `MUSIC_U`/`__csrf` 等白名单 Cookie、设备 ID 和随机 nuid，以及已验证账号 ID 和昵称。
- 酷狗：`kugou-app` 渠道的 `userid`、`token`、`dfid` 和 GUID/MID 来源；恢复时重新计算 MID，避免设备标识与 Token 渠道错配。
- 后台进程仍持有解密后的凭据用于请求；主进程只保存系统密钥密文。凭据不进入 renderer、preload、日志、截图或测试快照。

## 恢复与失效

- 恢复必须重新请求账号接口，不能仅凭“能解密”进入 connected。
- 账号 ID 与保存值不一致、会话过期、权限拒绝或响应格式无效时，后台结束会话并清理内存；启动恢复把对应保存项视为过期并删除。
- 网络/超时失败保留密文，界面显示失败状态，允许用户重新登录；不会自动无限重试。
- 解密失败或密文/文件损坏时进入 locked 状态。应用不覆盖原文件，用户可清除保存后重新登录。密钥轮换后的 `shouldReEncrypt` 提示当前未自动处理，仍可能通过旧密钥解密。
- `credentials.json` 不是数据库，也不保存歌曲、歌单或播放历史。

## IPC 与并发

- preload 只暴露 `credentials.getStatus()`、`setRemember(boolean)`、`clear()` 和 `onChanged(listener)`；没有读取任意密文、平台凭据或文件路径的方法。
- 主进程验证窗口/主帧/文档来源和参数；状态只包含白名单式的可用性、后端名、是否记住、是否锁定、已保存平台和安全错误，不含账号 ID、昵称或凭据。
- 登录、恢复和退出继续由各 Provider 的 generation 守卫处理；旧登录响应不能覆盖新会话。凭据保存失败不回滚已经成功的平台登录，但会在状态面板报告。

## 验证

- `pnpm test`：合成凭据 bundle 校验、保险库保存/读取/删除/关闭、不可用时不写文件、密文损坏锁定、文件权限、两个平台登录后导出与恢复。
- `pnpm test:e2e`：验证 preload 只暴露凭据白名单方法、状态投影，以及系统密钥不可用时不假装启用记住登录。
- `pnpm check`、typecheck、build、test:playback 独立于系统密钥服务。

当前开发机 `safeStorage.getSelectedStorageBackend()` 为 `basic_text`，因此真实系统密钥持久化和跨重启恢复**未在本机验证**；自动化用注入的 FakeCipher 验证保险库逻辑。真实 GNOME Keyring/KWallet、锁定与重启恢复需在具备安全密钥后端的 Linux 桌面补测。Windows/macOS 后端也未验证。

## 保存竞态与环境提示

退出单个平台、关闭记住登录或清除保存会使旧加密操作失效，即使旧操作较晚完成也不重新写回凭据；随后重新启用记住也不恢复已撤销项。主进程在异步导出后再次核对账号与 generation。自动化验证双平台保险库重建恢复及迟到写入丢弃。

Linux 若显示 basic_text/unavailable，请先通过系统设置启用并解锁 GNOME Keyring 或 KWallet，再重启应用；应用不会自动安装系统软件或改用明文。真实系统密钥后端下的跨重启验证仍需在相应桌面环境进行。
